# 0004. Phase 3A 전화 응대는 관리형 음성 런타임을 우선 검토

- 상태: **Proposed** (Phase 3A 착수 전 S5 결과로 확정)
- 날짜: 2026-11-15
- 관련: P3-01~03·09, R6, 이전 프로젝트 분석(02-architecture §7)

## 맥락
이전 전화 에이전트 프로젝트는 실시간 음성 계층(음성 감지·말 끊기·스트리밍 인식·TTS·발화 스케줄링)을 직접 구현하고 자체 모델 파인튜닝까지 시도했다. 같은 평가 하네스로 측정한 결과 관리형 음성 스택과의 품질 차이가 측정 노이즈 수준이었고, 점수를 실제로 움직인 것은 기반 모델 교체뿐이었다. 개발 인원 3~4명·8주 목표에서 실시간 음성 계층을 직접 만드는 것은 비용 대비 효과가 낮다.

## 고려한 선택지
1. **관리형 음성 런타임**(실시간 음성 API 또는 음성 에이전트 플랫폼) + 우리 tool·정책·접수 저장 — 빠름, 벤더 의존.
2. 직접 구현(STT+LLM+TTS 파이프라인, 턴테이킹 자체 제어) — 통제력 높음, 비용·리스크 큼.

## 결정 (제안)
1번을 우선 검토한다. 우리가 소유하는 것은 **tool 정의·접수 분류·정책·저장 경로(제안→승인)·eval**이고, 음성 입출력은 어댑터로 감싼다. 벤더 선정은 S5(국내 전화 연동)와 함께 판단하며, 통화 음성의 국외 전송은 Q9 결과를 따른다.

## 결과
- 좋아지는 점: 3A 일정 단축, 팀이 도메인 로직에 집중.
- 감수하는 점: 벤더 비용·종속, 국내 통신 연동 제약.
- 재검토 조건: 관리형 런타임이 국내 전화 연동·개인정보 요건을 충족하지 못할 때.
