# 0005. 이전 프로젝트 코드는 설계만 참고하고 새로 작성

- 상태: **Proposed** (11/17 D-03에서 합의)
- 날짜: 2026-11-15
- 관련: D-03, D-06, 02-architecture §7, 스킬 `legacy-code-analysis`

## 맥락
카본 님이 이전 프로젝트 3개(전화 에이전트, CRM 본체, 음성 CRM 런타임)를 비공개로 공유했다. 새 제품은 양방향 실시간 음성에서 **일방향 녹음+STT 후처리**로 바뀌었고, AI는 제안만 하고 원장이 승인한다. `legacy-code-analysis` 스킬로 세 레포를 분석하고 핵심 주장을 원본 코드와 대조했다(설치·실행 없이 읽기만).

## 고려한 선택지
1. **설계·스키마·규칙·tool 정의만 참고, 코드는 새로 작성** (작은 순수 함수·검증기·마이그레이션 패턴만 이식)
2. CRM 본체 코드를 기반으로 확장
3. 전화 에이전트 장부·예약 엔진을 기반으로 확장

## 결정 (제안)
1번.
- 2번 기각: 매장 전체를 메모리로 읽고 차이만 저장하는 구조라 **동시 이중 예약을 DB가 막지 못하고**, 영업시간 미검사·문자열 시각 비교·도달 불가 상태 등 결함이 있다. 결제·이용권 등 MVP 밖 도메인 비중도 크다.
- 3번 기각: 단일 매장(SQLite) 전제, 고객 전화번호 필수, AI 직접 확정 구조.
- 공통: 핵심 경로가 실시간 양방향 음성 전제.

참고 대상과 버릴 대상은 02-architecture §7 표를 따른다.

## 결과
- 좋아지는 점: 새 원칙(제안→승인, 강제 격리, DB 충돌 보장)을 처음부터 일관되게 적용.
- 감수하는 점: 이미 있는 기능을 다시 작성하는 시간. AI 코드 생성으로 상쇄 가능.
- 전제: 이식하는 작은 코드도 **권리 관계 확인 후**(Q22).
- 재검토 조건: 특정 모듈의 재작성 비용이 이식 비용보다 명백히 클 때 모듈 단위로 재판단.
