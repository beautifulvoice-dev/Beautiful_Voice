## 2. 개발 리더 역할 정의 (선정 기준)

리더는 "가장 잘하는 사람"보다 **통합·조율 시간을 확보할 수 있는 사람**이 맡는다.

- 아키텍처·계약(OpenAPI)·DB 스키마 최종 승인(CODEOWNERS)
- 스프린트 백로그와 PM 질문 창구 (개발 측 단일 창구)
- CI/CD·환경·시크릿 관리 책임
- 주 1회 기술 부채·리스크 점검, ADR 정리

### 주드(강성주) 검토 및 준비 상황 (2026-11-17)

- 공유된 코드의 분석 결과와 아키텍처 문서를 검토했으며, 기존 설계·스키마·업무 규칙·조회 도구를 참고하고 코드는 새로 작성하는 방향에 동의한다.
- [PR #10](https://github.com/parkganghyun123-sketch/Beautiful_Voice/pull/10)에서 예약 충돌 처리 설계를 검토하고 수정 요청 후 재리뷰·승인했다. 실제 PostgreSQL 제약과 동시 저장 검증은 S4에서 진행한다.
- 평가는 실제 원장 녹음과 사람이 작성한 정답을 사용하고, 메뉴·운영 규칙을 먼저 확정한 뒤 카본과 함께 설계한다.
- 공통 개발 규칙은 [04 개발 규칙](04-dev-rules.md)을 따른다. API 계약·DB 스키마 변경은 영향받는 담당자와 함께 검토하고, 개발 측 PM 소통·기능 통합·주간 리스크 점검·ADR 정리를 맡는다.
- CI/CD는 담당 범위이며, 기술 스택·배포 환경 확정에 맞춰 단계적으로 구성한다.

### Q6 동시 사용 의미

'최대 3명'은 **매장 3곳의 원장 3명**이 서비스를 동시에 사용한다는 뜻이다. 한 매장의 동시 예약 수를 3으로 설정하는 요구가 아니다. PR #11의 원장 승인 시 겹침 예약 허용 정책은 유지하며, 일반 충돌 차단과 명시적 강제 저장을 구분해 설계한다.

### Q12 참여 범위

카본은 하드웨어와 업로드 연결을 맡고 Phase 1 소프트웨어도 개발할 수 있다. 직접 개발 시 동일 저장소·데이터 모델·PR 규칙을 따른다. '개발 가능'은 Phase 1 전체 단독 담당 확정을 의미하지 않는다.

### Q22 코드 이전 허용

카본은 기존 코드가 본인이 만든 코드임을 PR #11 댓글에서 확인했고, 2026-11-16 새 공개 저장소로의 이전을 허용했다. 이 답변은 코드 이전 허용 범위이며 비밀값·실제 고객 데이터·비공개 분석 자료의 공개를 허용하지 않는다.
