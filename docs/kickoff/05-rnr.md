## 2. 개발 리더 역할 정의 (선정 기준)

리더는 "가장 잘하는 사람"보다 **통합·조율 시간을 확보할 수 있는 사람**이 맡는다.

- 아키텍처·계약(OpenAPI)·DB 스키마 최종 승인(CODEOWNERS)
- 스프린트 백로그와 PM 질문 창구 (개발 측 단일 창구)
- CI/CD·환경·시크릿 관리 책임
- 주 1회 기술 부채·리스크 점검, ADR 정리

## 3. 영역별 R&R — 기능(수직) 분담 ✅ 11/16 확정

3명이 FE/BE/AI로 레이어 분담하면 모든 기능이 3명의 동시 작업을 기다리게 된다. 그래서 기능 단위로 나누고 **공통 계층(계약·DB·CI)은 리더가 소유**한다.

| 영역 | 구체적으로 할 일 (포함 백로그) | 주담당 | 검토·지원 | 대체 | 필요 역량 |
|---|---|---|---|---|---|
| 개발 리더·서버 기반 | 프로젝트 세팅, 로그인, 공통 DB·API 설계, 배포, 전체 기능 통합 (COM-01~03, CI/CD, 환경) | **주드** | 미정 | 미정 | BE·인프라 |
| CRM·웹앱 | 고객 관리, 예약·캘린더, 예약 충돌 방지, 기록 확인·수정, AI 제안 승인 화면 (P1-08·09, P2-01~04·09·10·11, 승인 UI, 스파이크 S4) | **옵마** | 카본(UX) | 미정 | FE+BE 풀스택 |
| 음성·AI | 음성 업로드, STT, 발화 내용 구조화, 기록·조회·변경 구분, AI 변경 제안 생성 (P1-02~07, P2-05·06·08의 AI 부분, 스파이크 S1·S2·S3) | **해나** | 미정 | 미정 | BE·LLM·평가 |
| 하드웨어·업로드 | P1-01, S3(기기 쪽) | 카본 | 해나(음성·AI) | | HW |
| 전화·발송 연동 | P3, S5 | 3A 착수 시 지정 | 카본(현장) | | 연동 |

- P2-07 채팅 질문은 화면을 CRM·웹앱(옵마), 질의 엔진을 음성·AI(해나)가 맡는다. P2-05와 같은 조회 기능을 공유한다. ASSUMPTION: 표의 백로그 매핑은 개발팀 해석이며 스프린트 플래닝에서 조정한다.
