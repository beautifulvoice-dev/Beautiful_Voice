## 3. Eval 설계 원칙 (이전 프로젝트 교훈)
이전 전화 에이전트 프로젝트의 자체 평가 세트는 제품을 바꾸지 않고 측정 도구만 바꿔도 점수가 크게 움직였다. 원인과 새 원칙:

| 이전 결함 | 새 원칙 |
|---|---|
| 고객 발화를 LLM이 생성, 방언 과장·소음을 글자로 흉내 | 입력 = **원장 본인 실제 녹음**(가명 고객). LLM 생성 발화 금지 |
| 메뉴·가격·소요를 무작위 생성, 회차권을 1회 슬롯으로 처리 | **도메인 카탈로그(메뉴·소요·회차권·운영 규칙)와 정책을 정답보다 먼저 확정** — 카본 공동 작업 |
| 정답에 미확정 정책·고정 문구, 정답을 평가 대상 엔진으로 계산 | 정답은 **사람이 작성**, 구조·값으로 채점(문구 일치 금지) |
| STT·이해 오류가 섞여 원인 분리 불가 | **STT 평가와 구조화 평가 분리**(정답 전사 / STT 전사 기준 각각 채점) |
| 환각을 별도로 보지 않음 | 필드별 채점 + "말하지 않음 = null"을 정답에 명시해 **환각률 별도 측정**. 모호한 입력은 "확인 필요"가 정답 |
| 파일럿이 노이즈보다 작음, 채택 기준 사후 완화, holdout 오염 | 같은 입력 3회 이상 반복으로 **노이즈 바닥 먼저**, 채택 기준 사전 고정, holdout 봉인, "아무것도 안 함" 기준선 |
