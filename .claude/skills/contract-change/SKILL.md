# 계약 변경 절차

> 스택 확정 전에는 1~2단계(계약 문서)까지만 수행한다.

1. **영향 확인:** 이 계약을 쓰는 쪽(웹앱·기기·워커·전화 어댑터)을 나열한다. 기기 펌웨어가 쓰는 엔드포인트면 하위 호환 필수.
2. **계약 먼저 수정:** OpenAPI 파일에 변경을 반영한다. 규약 — 오류 `{code,message,details}`, 쓰기 API는 `Idempotency-Key`, 시각은 ISO-8601+offset, 목록은 cursor 페이지네이션, 모든 리소스는 shop 범위.
3. **호환성:** 필드 삭제·의미 변경·enum 값 제거는 breaking. breaking이면 새 버전 경로 또는 단계적 폐기 계획을 PR에 쓴다.
4. **생성·구현:** 타입/클라이언트 재생성 → 서버 검증 → 도메인 서비스 → 클라이언트 순서.
5. **테스트:** 계약 테스트(요청/응답 스키마 검증) + 멱등 재전송 테스트 + 다른 shop 접근 거부 테스트.
6. **리뷰:** PR에 계약 diff를 요약하고 개발 리더(CODEOWNERS)를 리뷰어로 지정한다.
